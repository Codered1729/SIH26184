# Phase 7 Context: ML Evaluation Integrity & Industry-Standard Metrics

**Source**: Decisions captured from ML analysis session (2026-09-30)  
**Analyst**: Antigravity IDE  

---

## Problem Statement

The SENTINEL ML evaluation pipeline has four confirmed issues discovered through code and results analysis:

1. **Train-set leakage (CRITICAL)**: `train_and_serialize.py` evaluates all metrics on the same data used for training. The documented metrics (CatBoost PR-AUC: 0.881, F1: 0.829) are training-set inflated. The honest walk-forward benchmark results are PR-AUC ~0.518, F1 ~0.524.

2. **Missing industry-standard metrics**: ROC-AUC, KS Statistic (standard in Indian RBI fraud models), and Expected Calibration Error (ECE) are not computed anywhere.

3. **Circular Hawkes benchmark**: `validate_hawkes.py` selects the ground-truth target ATM using `weights = [math.exp(-d / 2.0) for _, d in nearby]` — the exact same exponential spatial decay kernel the Hawkes ranker uses. Self-validating, not predictively valid.

4. **Brier Score above industry target**: Current Brier Score 0.1745 is above the < 0.15 target. Isotonic calibration on a held-out calibration split should close this gap.

---

## Design Decisions

### DD-01: Temporal holdout split strategy
- Use `shuffle=False` train_test_split with `test_size=0.20` to preserve time ordering
- The last 20% of the timeline (by `day` column) becomes the holdout test set
- Benchmark script already does this correctly via walk-forward — the fix targets `train_and_serialize.py`

### DD-02: Metrics to add
- **ROC-AUC**: `roc_auc_score(y_test, y_prob)` from sklearn
- **KS Statistic**: `ks_2samp(y_prob[y_test==1], y_prob[y_test==0]).statistic` from scipy
- **ECE (10-bin)**: Manual bin loop — (bin_count / n_total) * |mean_predicted - mean_actual|

### DD-03: Hawkes benchmark fix
- Change ground-truth ATM selection from weighted (exponential decay) to uniform random from the `nearby` list
- Decouples the evaluation criterion from the model's scoring function

### DD-04: Calibration approach
- Use `CalibratedClassifierCV(estimator=catboost_model, method='isotonic', cv='prefit')`
- Fit on a dedicated 10% calibration split held out from the main train/test split
- Store calibrated model alongside uncalibrated version in bundle (backward compatible)

### DD-05: Documentation update scope
- `docs/DESIGN_DECISIONS_AND_METRICS.md` Section 3 benchmark table updated with honest holdout numbers
- `experiments/model_comparison.md` and `.csv` are re-generated by running `benchmark_models.py`

### DD-06: No model replacement
- No retraining of production model needed — fixes are to evaluation scripts only
